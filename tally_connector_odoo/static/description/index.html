A queue, not a gamble

Every sync is handed to a background job the moment you post a document — it never blocks your screen waiting on a slow network or an idle Tally window. The job is retried on your terms, and its outcome is always written back onto the exact record you posted, so what Odoo shows always matches what actually happened.

Pick the topology that fits your network

Both modes run the same sync engine underneath — the only difference is how the request reaches Tally.

DIRECT — Odoo connects to Tally

Best when Odoo already has private network access to the Tally machine — over a site VPN, Tailscale, or a shared LAN.

  • ✓ No extra software to install on the Tally PC
  • ✓ Odoo calls Tally's HTTP/XML listener directly
  • ✓ Requires the network path to already exist
AGENT — Tally's PC connects to Odoo

Best when there's no VPN and you don't want to open an inbound port — the Agent only ever calls out, and queues work the moment it comes online.

  • ✓ One small program, no installer, no admin rights
  • ✓ Polls Odoo for work, talks to Tally on localhost
  • ✓ Works behind any firewall or NAT unmodified

Six steps, one working sync

This is the Agent path — no network changes needed. Direct mode skips straight to filling in Tally's host and port.

1  Create a connection in Odoo
  • Open the Tally Connector app, go to Tally Connections
  • Create a new connection, name it, and select your Company
  • Set Connection Mode to “Agent (preview)” and save
2  Generate your Agent token
  • Click Generate Agent Token on the connection
  • Copy the token immediately — it's shown once and can't be retrieved again
  • Generating a new token later immediately revokes this one — the Agent using it will need the new token too
3  Download the Agent

On the PC where Tally actually runs, download the Agent from:

https://digimonk.in/agent-download

  • Extract the zip to any folder
4  Run the setup wizard
  • Double-click run_agent.bat
  • Enter your Odoo URL, database name, and the token from step 2
  • Tally host/port defaults to localhost:9000 when it's the same PC
  • The wizard writes config.json for you
5  Confirm it's working
  • The Agent window shows “Registered…” and “Local Tally is now reachable” once setup completes
  • In Odoo, the connection shows Online and Tally Reachable in green under Agent Devices
  • Click Test Connection — it shows “Testing” for a few seconds, then settles to “Connected”
6  Keep it running automatically
  • Press Win+R, type shell:startup, press Enter
  • Add a shortcut to run_agent.bat in that folder
  • The Agent now starts on every login — no manual step left

The five messages you'll actually see

Every state the Agent or connection can show, and exactly what to do about it.

Connection shows “Testing” and doesn't change
This is normal, not stuck. Clicking Test Connection queues a check for the Agent to pick up — it settles to Connected or Failed within a few seconds. Refresh the page once, rather than clicking the button again.
Agent window says “Invalid or revoked token”
A new Agent Token was generated for this connection since this Agent last started — generating a token always revokes the previous one immediately, on purpose. Generate a fresh token, update config.json, and restart run_agent.bat.
Connection shows “Online” but nothing is syncing
Check Enabled for Sync is switched on, and open View Agent Sync Timeline — a record stuck in “Queued” for more than a minute usually means the Agent window has been closed.
“Could not reach Odoo to poll (502 Bad Gateway)” in the Agent window
A brief, one-off gap reaching your Odoo server. The Agent retries on its own every few seconds; no action needed unless it repeats for more than a minute.
A record shows “Failed” with a real error message
A genuine rejection from Tally itself (a missing ledger, a closed period, a mismatched Stock Item). Fix it in Tally or in the mapping, then use the record's own Sync to Tally button to retry — safe to retry any number of times.
